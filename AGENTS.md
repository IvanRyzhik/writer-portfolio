# AGENTS.md — Writer Portfolio

Persistent guidance for AI agents working on this codebase.

## Project Overview

A single-page **Next.js writer portfolio** that lists articles with lazy-loading cards, an iframe modal for inline reading, and a hero section. Deployed to **Cloudflare Pages** via `@cloudflare/next-on-pages`.

---

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | Next.js (Pages Router) |
| Language | TypeScript (`strict: false`) |
| Styling | Tailwind CSS 3 + Flowbite / flowbite-react |
| Animation | Framer Motion |
| Modal | react-modal (iframe for external articles) |
| Carousel | react-slick |
| Deployment | Cloudflare Pages + wrangler |
| Linting | ESLint 9 + TypeScript / React / import / a11y plugins |
| Formatting | Prettier (`printWidth: 100`, `tabWidth: 2`, single quotes, semicolons, trailing commas) |

## Component Conventions

- **File layout**: `src/components/ComponentName/ComponentName.tsx` — one folder per component, default export.
- **Typing**: Use explicit `type` for props (e.g. `type ArticlesGridProps = { ... }`). Mixing `React.FC<Props>` and plain function signatures is acceptable.
- **React import**: Import `React` explicitly at the top of every component file.
- **Path aliases**: Prefer `@components/ComponentName` over relative paths. Defined in `tsconfig.json`:
  - `@components/*` → `src/components/*`
  - `@hooks/*`, `@lib/*`, `@config/*` (reserved for future use)
- Avoid adding new folders directly under `src/` without updating `tsconfig.json` path aliases.

---

## Styling Conventions

- Use **Tailwind utility classes** for layout, spacing, responsive breakpoints (`md:`, `lg:`), and typography.
- Custom one-off styles belong in `styles/global.css` as named classes (e.g. `.gradient`, `.block-shadow`).
- Flowbite `Card` is used for article tiles; pass a `theme` override object to adjust internal layout — do not override Flowbite internals via global CSS.
- Use **`next/image`** (`Image`) for the hero and any new images that benefit from optimisation. Article card thumbnails use plain `<img>` for simplicity (external URLs not in the allowlist).
- Only `source.unsplash.com` is in `next.config.js` `images.domains`. Add new remote domains there if switching to `next/image` for external sources.

---

## Data Layer

- Article data lives in **`source/articles.js`** as a plain JS array. There is no CMS or API.
- Each article object fields: `title`, `description`, `image`, `url`, `source`, `remoteAccess` (bool).
- `remoteAccess: true` → "Read Here" button opens an iframe modal. `false` → "View Source" external link only.

---

## Page Architecture

`pages/index.tsx` is the single marketing page. It:
1. Holds `useState` for the selected article / modal open state.
2. Renders `<SeoHead>`, `<Hero>`, `<ArticlesGrid>`, `<ArticleModal>`, `<Footer>` in order.
3. Is marked `'use client'` at the top (needed for hooks inside Pages Router).

`ArticlesGrid` uses `IntersectionObserver` with a sentinel div to progressively reveal cards in batches — do not remove this pattern when modifying the grid.

---

## Accessibility

- Always provide `aria-label` on icon-only buttons and links (see `Footer` LinkedIn link and modal close button as examples).
- `ArticleModal` calls `Modal.setAppElement('#__next')` — keep this in place to avoid screen-reader issues.
- Use semantic HTML elements (`<section>`, `<footer>`, `<h1>`–`<h3>`) rather than generic `<div>` where appropriate.

## Cloudflare Pages Notes

- Build output goes to `.vercel/output/static` (generated by `next-on-pages`).
- `wrangler.jsonc` sets `nodejs_compat` compatibility flag — required for Next.js edge APIs.
- Do not use Node-only APIs (e.g. `fs`, `path`) in component or page code; they are not available in the Cloudflare Workers runtime.
- `NEXT_PUBLIC_GA_ID` env var enables Google Analytics via `SeoHead` — set it in Cloudflare Pages environment variables for production.

## What NOT to Do

- Do not migrate to the **App Router** without a deliberate decision — the project is Pages Router only.
- Do not add server-side `getServerSideProps` — Cloudflare Pages static output does not support it. Use `getStaticProps` or client-side fetching.
- Do not import from `../../../source/articles` using deep relative paths — always use `@components/...` or move data to a proper `src/data/` folder with a path alias.
- Do not commit `.vercel/` or `.wrangler/` output directories.
